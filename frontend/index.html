🎯 Problem & The "Prevention Gap"
Key Pitch: Traditional LLM cost governance is exclusively post-facto: teams receive a massive bill at month's end and look at retrospective dashboards. By then, the money is already gone.

The Gap: Saksham_AI introduces prevention at keystroke time. Vague prompts trigger costly follow-up messages where the entire context window is resent, multiplying spend. Saksham_AI prevents this before the prompt ever hits the wire.
📊 Why This Links to Data & Analytics
Key Pitch: This is a core data and analytics project. It captures granular telemetry, models multi-variable pricing and environmental footprints, writes to a relational SQL schema, and surfaces actionable business intelligence.

BI Impact: Enterprise leaders can track optimization adoption, calculate realized vs missed ROI, and export data directly into Power BI to govern organizational AI spending.
⚙️ Token Counting & Nuances
Key Pitch: A token is not a word; roughly 4 characters or ~0.75 words in English. Different LLM architectures use different vocabulary tokenizers (e.g. OpenAI uses Byte-Pair Encoding cl100k/o200k, while Claude and Gemini utilize proprietary variations).

Accuracy: Local counting via tiktoken provides sub-millisecond pre-send speed; post-execution, the verifiable API response figures audit the actual usage.
⚖️ Heuristic vs LLM Judge Trade-off
Key Pitch: Using an LLM to evaluate every keystroke is economically flawed and creates high latency. Saksham_AI uses a deterministic 0-100 weighted heuristic engine running in <1ms at $0 cost.

Breakeven Insight: A rewrite itself costs tokens. For single one-off queries, local compression pays off immediately, whereas an LLM rewriter pays off when prompts are reused (system prompts, batch templates).
